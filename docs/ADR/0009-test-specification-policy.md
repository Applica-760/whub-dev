# ADR-0009: テスト仕様化ポリシー

- **Status:** Accepted
- **Date:** 2026-07-07

## Context

- 既存テストはAI提案を十分に検証せず承認したものが含まれ、正しさの根拠として扱えない
- whubはローカルfilesystem・SSH・sshfs・rsync・subprocessを扱うため、無制限に実行すると実環境へ副作用が出る
- テスト追加時にケースの合意なしで実装へ進むと、同じ問題を再生産する

## Decision

- テストの仕様根拠は `docs/knowledge.yaml`、現行実装、実際のCLI境界を優先する
- 既存テストは仕様根拠にせず、見落とし確認と流用候補としてのみ参照する
- 各領域のテスト実装前に「検証するケース」「検証しないケース」を提示し、合意後に実装する
- 各テストファイル冒頭に日本語docstringで番号付きケース一覧を書く
- テストコード中の対応箇所には説明文を書かず、`# ケース1`のように番号だけを書く
- private関数は原則テストしないが、副作用境界・複雑分岐は例外的に直接テストしてよい
- SSH・sshfs・rsync・umount・diskutilなど実環境依存の外部操作は実行せず、argv・入力・失敗時表示をmockで検証する
- ファイル書き込みは一時ディレクトリ内に限定する

## Rationale

- テストコード自体を仕様文書として読める形にし、何を保証して何を保証しないかを明示する
- ケース番号でdocstringと実装箇所を対応させることで、説明コメントの重複を避ける
- 副作用境界を固定することで、Macローカル専用CLIとしての安全性を保ちながら回帰検出できる

## Consequences

- 新しいテスト追加は、ケース一覧の確認を挟むため実装速度より品質を優先する
- 既存テストの移植時も、旧テストの期待値をそのまま採用せず仕様根拠を確認する
- 結合テストで実SSH等を使いたい場合は、このADRとは別に明示的な手動検証または隔離環境の方針を定める
