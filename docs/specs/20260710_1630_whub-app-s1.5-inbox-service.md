# 実行仕様書: whub app S1.5 — inbox投函のservices層

## 目的
- Web appからのinbox投函の土台として、`vault/inbox/`へノートを作成するservices関数を追加する

## 背景・前提
- 全体ロードマップは`docs/tasks/20260708_2108_existing-features-html-view.md`を正とする
- inboxの役割: 対話抜きで思いつきを書き殴る摩擦ゼロの投函口。project非紐付けでbacklogとは別軸。会話・整理は投函後のSkill（refile等）が担う（2026-07-10整理）
- 層の規約はS2a（`docs/specs/20260710_1319_whub-app-s2a-service-extraction.md`）で確立済み: servicesはClick/HTTP非依存、失敗は`ServiceError`系
- inboxのCLIコマンドは作らない（決定済み）

## 対象範囲
- `src/whub/services/inbox.py`（新規）
- services単体テスト

## 非対象範囲
- APIエンドポイント（S2bで追加）
- UIフォーム（S4で追加）
- refile Skillの拡張（別task md）
- 既存inboxノートへの操作（読取・一覧・削除は投函口の責務外）

## 変更要件
- `services/inbox.py`
    - `create_inbox_note(manifest, title, body) -> Path`: `vault/inbox/`へノートを作成し、生成ファイルのPathを返す
    - 保存先はmanifestの`vault` projectのworkspace_pathから解決する。vault未定義・未link時は`ServiceError`
    - ファイル名は`YYYYMMDD_HHmm_<title>.md`（日時は現在時刻から自動付与、task md命名と同形式）
    - titleはstripして空なら`ServiceError`（入力必須）。パス区切り等ファイル名に使えない文字は黙ってsanitizeせず`ServiceError`
    - bodyはstripして空なら`ServiceError`（空ファイルはrefileのノイズになるため不許容）
    - 本文はbodyをそのまま書き込む。frontmatter・タグは付けない（refile時に付与）
    - 同名ファイルが既に存在する場合は`ServiceError`（上書きしない）

## 実装方針
- S2aで確立した層規約に従う: `click`への依存を持たず、例外は`services/errors.py`の`ServiceError`を使う
- vaultの解決はmanifest（SSOT）経由とし、固定パスやdata_dir由来の暗黙規約に依存しない

## 受け入れ基準
- [x] `create_inbox_note`が`vault/inbox/`へ`YYYYMMDD_HHmm_<title>.md`を作成し、本文がbodyと一致する
- [x] 空title・空body・ファイル名に使えない文字・同名衝突・vault未link時がそれぞれ`ServiceError`になる
- [x] 生成ノートにfrontmatter・タグが付与されていない
- [x] `services/inbox.py`が`click`をimportしていない
- [x] `uv run pytest`が全件通る（新規テストを含む）

## 検証条件
- 自動: 一時ディレクトリにvault相当の構成とmanifestを注入し、正常作成・命名形式・各異常系を単体テストで検証する
- 手動: 実vaultへ1件投函し、ファイル名・本文を確認する（確認後はrefileで処理するか削除する）

- 日時はMacのローカル時刻。localhost限定のためタイムゾーンは考慮しない
