# 目的・前提・方針案

## 目的
`whub todo` コマンドを追加し、生活・事務・開発を横断する個人のやることを外部記憶化する。

## 確定事項
- `whub todo` をサブコマンド方式で実装（add, done, rm, list）
- データモデル: id, title, project, priority, done, created_at, due_date, done_at
- priority は whub state と同じ体系 (red/yellow/blue/none)
- project は manifest resource との紐づけ（任意）
- project に属さない生活・事務タスクも同じ一覧で管理
- created_at は発行日として `todo add` 実行日を自動保存
- due_date は任意の締切日とし、日付のみを `YYYY-MM-DD` 形式で保存
- 一覧では発行日を常時、締切日は設定されたtodoのみ表示
- TUI(curses)は初期スコープ外
- todos.yaml は `.whub/todos.yaml` に配置し、`~/.whub/`・config.yaml・グローバル化は永久に非対象
- todo は detail/roadmap のパスやスキーマを持たない

## 運用フロー
- `whub todo` と `whub status` で全体のタスクと優先度を把握
- `whub cd` で対象projectへ移動し、`docs/roadmap.md` で長期計画を確認
- 個別作業は `/task-planning` で実行計画を作成して進める

## 責務
- todo: project所属を必須としない、実行可能な単発アクション
- roadmap: projectごとに `docs/roadmap.md` として持つ長期計画
- task-planning: 個別作業の実行計画と記録

- 単発アクションは段階的にwhub todoへ、projectの長期計画は各projectのroadmapへ移行予定（このタスクのスコープ外）
