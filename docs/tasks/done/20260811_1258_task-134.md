# Agent worktree session resolutionを高速化

## Objective

WebappのTerminalページのworktree走査、およびworktree sessionへの入退室を遅延させる全件Task走査・逐次存在確認を解消する。

## Approach

- worktreeの規約パスをTask全件読込なしに解決できる境界を設け、Web session一覧とworktree attach/detachで必要な確認だけを行う。ローカルとremoteの両方を対象に回帰テストで検証する。

## Context

### 確認済みの事実

- `list_agent_sessions` はProjectの全Taskを読み、各Taskごとにworktree存在確認とtmux session解決を行う。Web APIはその後に同じTaskのworktreeを再解決する。
- `resolve_project_worktree` はTask recordの全件読込を伴う。`whub worktree open` は既存worktreeでもこの経路を通るため、再接続時にもTask数に比例して遅くなる。
- Terminalのworktree WebSocket接続も同じresolverを通る。Operator Terminal WebSocket接続は通らない。
- TASK-130でProject単位のWeb取得には分離済みだが、Project内の逐次走査は残っている。

### 解決の方向性（要実装時確認）

- Task IDから規約worktreeパスを導出する処理を、Task record全件読込と分離する。
- Agent session一覧はtmux側を起点に稼働sessionだけを特定し、worktree確認を必要な対象に限定する。Web APIの重複解決を除去する。
- Operator Terminalへ戻る際の遅延は、画面側でAgent session一覧を再取得している場合に上記で解消する。実装前にフロントエンドの遷移経路で確認する。

## Plan

1. Task全件走査を要する箇所と、Task IDから規約worktreeを導出できる箇所を分離し、入退室・一覧で必要な最小の存在／tmux確認へ置換する。
2. Web APIで重複するworktree解決を除去し、localとremoteの失敗分離を維持する。
3. resolver、Agent session一覧、worktree open/close、Terminal接続のfocused testを追加・更新し、`uv run pytest`で検証する。
