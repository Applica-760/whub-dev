# TerminalPageからOperator Terminal状態を分離

## Objective

TerminalPageが持つOperator Terminalの一覧取得・起動・停止・pending・errorを具体的なhookへ分離し、Pageを画面調停へ近づける

## Approach

- 既存のagentSessions.tsを踏襲してoperatorTerminals.tsへuseOperatorTerminalsを実装する。generated schema型とerrorMessageを再利用し、confirm・起動後の選択・attentionはTerminalPageに残す。挙動は変更しない

## Context

- `TerminalPage.tsx:46-49,197-268`がOperator Terminalの状態、GET・POST・DELETE、error・pendingを保持している。
- `agentSessions.ts`には同種の「API取得と状態を具体hookへ置く」既存境界がある。
- Operator APIの型は`app/src/api/generated/schema.d.ts`に存在し、error変換は`app/src/api/errorMessage.ts`を再利用できる。
- ユーザー判断により`implementer` authのTask worktreeで実装する。

## Scope

- `operatorTerminals.ts`へOperator一覧・起動・停止・pending・errorを分離する。
- `TerminalPage`はconfirm、起動後の選択、attention、routing、terminal選択ライフサイクルを保持する。
- terminal選択、lazy mount、reload、Task panel、shortcutの分離は対象外とする。

## Plan

1. Task worktreeを`implementer` authで開き、Task pairとProject指示を再読込する。
2. 既存のTerminalPage focused testとtypecheckをbaselineとして実行する。
3. generated schema型と`errorMessage`を使う`useOperatorTerminals`を`operatorTerminals.ts`へ実装する。
4. `TerminalPage`のOperator API・状態をhook利用へ置換し、confirmと起動後の選択をPageに残す。
5. Operator lifecycleのfocused testと既存Page契約を検証し、format・typecheck・build・全testを実行する。
6. CodeGraphで影響範囲を再確認し、変更をcommitする。

## Acceptance Criteria

- 初期一覧取得、起動、指定IDだけの停止、pending、error表示の挙動が変わらない。
- 起動したOperatorが選択され、停止確認はPageのUI責務として維持される。
- attention、routing、terminal mount・reloadには変更を加えない。
- 汎用CRUD、repository、Context、reducerを追加しない。
