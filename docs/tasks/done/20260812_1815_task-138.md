# Web Terminalの接続・切替を安定化する

## Objective

TASK-137の変更を含まない現行mainを基準に、Terminal画面を保持したまま切替・入力・休止復帰を安定化し、Task詳細の不要なページ遷移とworktree parentを持たないProjectのExplorer警告を除去する

## Approach

- Terminalごとの画面と接続をmountしたまま可視性だけ切り替え、既存のWebSocket再接続パターンとterminal bridge契約を再利用して接続ライフサイクルを根本修正した上で、非worktree Projectを正常な空sessionとして扱う

## Context

- `TASK-137`の変更案は実ブラウザ検証で悪化を確認してrevertし、Taskをcancelした。本Taskは現行mainを基準にWebSocket・controller lease・xterm bufferのライフサイクルを扱い、resize修正は対象外とする。
- 現行`useTerminalConnection`は切断後に再接続せず、WebSocketがOPENでない入力とserverの文字列error frameを破棄する。放置後の入力不能とclaim失敗の不可視化に一致する。
- Terminal選択変更は`key={selectedTerminal}`でxterm・WebSocket・表示bufferを破棄するため、再選択時は新規attachからの再描画待ちとなる。
- `/terminal`と`/terminal/explorer`は同じ`TerminalPage`内で表示を切り替える一方、Task詳細ページへの遷移は`TerminalPage`をunmountする。worktree TerminalのTaskグラフは選択callbackがなく、ノード選択時にTask詳細ページへ遷移する。
- `Cmd+Shift+O`と`Cmd+Shift+E`はwindowのcapture listenerで処理する実装だが、Terminal以外へfocusがある場合に反応しない。Terminal内の各ペインから同じ操作ができることを回帰条件とする。
- xtermへの出力にはbackpressureがなく、background throttlingや大量出力後のwrite queue滞留が入力echo遅延とfreeze様挙動の候補である。frontend内のqueue追加だけを根治策にしない。
- Agent session APIはRemote Resourceの`ServiceError`だけを空一覧へ変換するため、worktree parentを持たないlocal Projectでは期待されたsession不在がExplorerの警告になる。

## Plan

1. `TASK-137`の変更を含まない現行mainを基準に、Terminal切替、WebSocket切断、browser休止復帰、継続出力を再現し、resize残件と接続・出力queueの問題を分離する。
2. 既存`useApprovalAttention`の再接続パターンを再利用し、切断後の再接続・controller再claim・protocol error表示を実装する。接続前後の入力を無言で破棄しない契約をテストで固定する。
3. 各Terminalは初回選択時に可視領域でxterm・WebSocket・表示bufferをmountし、以後は保持して選択変更と`Cmd+Shift+↑↓`では可視性だけを切り替える。未選択Terminalを先行mountせず、非表示Terminalから不正なresizeを送らず、focusを奪わないことを検証する。各Terminal行には、tmux sessionを残したまま対象xterm・WebSocketだけを可視状態で再mountする再読込操作を設ける。
4. worktree TerminalでもTaskグラフのノード選択を下部の詳細表示だけに反映し、Task詳細ページへ遷移させない。
5. `Cmd+Shift+O`と`Cmd+Shift+E`をTerminal内のTask・Terminal・Explorerのどこにfocusがあっても動作させる。
6. 大量出力またはbackground復帰でxterm write queue滞留を再現できた場合だけ、terminal bridgeを含むflow controlを追加する。再現できなければ推測によるprotocol拡張は行わない。
7. worktree parentを持たないProjectをAgent session APIで正常な空一覧として扱い、その他の実障害は警告として維持する。APIとTerminal Explorerの回帰テストを追加する。
8. focused test、frontend全test、`npm run typecheck`、`npm run build`を実行し、browser起動はユーザー確認後に切替・休止復帰・継続出力を確認する。
