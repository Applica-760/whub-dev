# 目的・前提・方針案

## 目的
projectごとの`docs/roadmap.md`へ思いつき・新機能案を素早く追記し、後からSkill/Agentで洗練する導線を作る。

## 前提
- roadmapは`<project>/docs/roadmap.md`の1ファイルだけを使う
- `whub roadmap <project> <text...>`で未整理メモへ追記する
- `whub roadmap <project>`のような本文なし実行はエラーにする
- `init`や`list`は作らない
- ファイルが存在しなければテンプレート付きで生成する
- ファイルが存在すれば末尾の未整理メモへ追記する
- 整理済みロードマップを上部、未整理メモを末尾に置く
- 内容の整理・分類・昇格はCLIではなくSkill/Agent側で行う

## 方針案
- CLIはroadmapファイルの存在保証と未整理メモ追記だけを担う
- Skillは未整理メモを壁打ちで洗練し、整理済みロードマップ・todo・task-planning・specs・ADRへ分解する
- project解決は当面manifest resource名に従い、project/resource再設計後に拡張する

# 計画

## Phase 1: CLI仕様の固定
- [ ] `whub roadmap <project> <text...>`の引数・エラー・出力仕様を決める
- [ ] roadmapテンプレートの見出しと追記フォーマットを決める

## Phase 2: CLI実装
- [ ] `src/whub/commands/roadmap.py`を追加し、projectの`docs/roadmap.md`へ追記する
- [ ] `src/whub/cli.py`へ`roadmap`コマンドを登録する
- [ ] symlink resourceのpath解決を実装し、remote resourceは初期スコープ外にするか方針決定する

## Phase 3: Skill設計
- [ ] roadmap未整理メモを整理済みロードマップへ昇格するSkillの責務を定義する
- [ ] todo/task-planning/specs/ADRへ分解する判断基準を定義する
- [ ] boot配布対象にするか、workspace-hub内専用にするか決める

## Phase 4: 検証
- [ ] 新規roadmap生成と既存roadmap追記を実コマンドで確認する
- [ ] 本文なし実行と未知projectの異常系を確認する
- [ ] 必要最小限の自動テストを追加する
