# リモートマウントのAppleDouble対策

## 目的・前提・方針案

- macOSからsshfs/FUSEマウントへアクセスした際の`._*`生成と、`whub boot`のリモート全体走査による停止を解消する
- SSH・VS Code Remote SSHでは処理がリモート側で完結するため、macOS由来のAppleDouble生成を原則回避できる
- 通常のsymlinkはSSH先を直接参照できず、ローカルパス化にはマウントまたは同期層が必要
- 既存のsshfs運用を即時廃止せず、Remote SSH・明示同期・マウント継続のトレードオフを比較する
- AppleDoubleの常時清掃はbootの責務から外し、生成抑止・無視・必要時清掃へ分離する

## 計画

### Phase 1: 確認済み不具合の修正
- [ ] `whub boot`の対象全体に対する`rglob("._*")`を廃止し、リモート全走査を発生させない
- [ ] AppleDouble除去を廃止するか配布対象パスだけへ限定するか、実測結果から決定する
- [ ] 配布開始・CodeGraph初期化開始を対象別に表示し、停止箇所を判別可能にする
- [ ] `codegraph init`へtimeoutを設け、1対象の停止で後続処理を塞がない

### Phase 2: AppleDoubleの運用対策
- [ ] Git・VS Code・CodeGraphで`._*`を無視する設定範囲と副作用を確認する
- [ ] sshfs/FUSE-TでAppleDoubleまたは拡張属性生成を抑止できるオプションの有無を実環境で確認する
- [ ] 必要時だけ対象を限定して清掃するコマンドまたは運用手順を定義する

### Phase 3: リモートアクセス方式の比較
- [ ] VS Code Remote SSHを、AppleDouble非生成・編集性能・Claude/Codex利用可否で評価する
- [ ] SSH上のCLI編集を、Agent実行・CodeGraph初期化・ファイル参照の観点で評価する
- [ ] rsync等の明示同期方式を、競合・遅延・ローカルツール互換性の観点で評価する
- [ ] sshfs継続を、統合ツリーの利便性とメタデータ・性能問題の観点で評価し採用範囲を決める

### Phase 4: 回帰検証
- [ ] 大規模な隔離ディレクトリでbootが全体走査しないことを検証する
- [ ] 遅い・応答しない対象を模擬し、後続対象が継続処理されることを検証する
- [ ] ローカルsymlink・sshfs mountの双方で既存配布仕様が維持されることを確認する

## 実行ログ

### 試行 1: CodeGraph初期化が停止原因
- 実施内容: 停止中プロセス、出力位置、`.codegraph`生成有無を確認した
- 結果: `esn-lab`の`done`前でCodeGraph子プロセスもなく、配布処理内で停止していた
- 判断: 棄却

### 試行 2: AppleDouble全体清掃がリモートI/Oを増大
- 実施内容: boot実装とマウント状態を確認し、対象全体の`rglob("._*")`を特定した
- 結果: NFS/FUSE越しにリポジトリ全体を同期走査するため、配布量11ファイル・44KBと無関係に停止し得る
- 判断: 続行
