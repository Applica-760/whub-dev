# Workspace Hub: 要求定義書

## 1. 背景と目的

複数のPC・複数のプロジェクトにまたがる開発作業を、1つのディレクトリツリーとして統合し、俯瞰・操作・AI連携を一元化する。

### 1.1 解決したい課題

| # | 課題 | 現状 |
|---|------|------|
| 1 | 作業状態が分散している | PC・プロジェクトごとに個別確認が必要 |
| 2 | AIへのコンテキスト提供が手動 Agentルール管理が分散している | (https://github.com/Applica-760/.my-boot)を作成したが、　共通規約・Skill・MCP設定を各プロジェクトに個別配布（.my-boot install.sh）しており、更新時に*全プロジェクトを手動で回る必要がある* |
| 4 | Git操作が個別 | リポジトリごとにfetch/pullを手動実行 |
| 5 | Git管理外ファイルへのアクセスが困難 | データセット等はSSH接続して直接操作 |
| 6 | リモートPCの操作が断片的 | ターミナルを都度開いてSSH接続 |
| 7 | ローカルファイルのSSOT問題 | workspace-hubにファイルを移動すると原本の所在が分散し、日常のPC操作（検索等）に支障が出る |

### 1.2 ゴール

- ローカルの1ディレクトリを開くだけで、全プロジェクトの状態が見える
- Claude Codeを起動すれば、適切なコンテキストが自動で渡る
- 1コマンドで全リポジトリの同期が完了する
- リモートPCのファイルもローカルと同様に閲覧できる
- リモートPCへのコマンド実行を抽象化された形で行える
- ローカルの既存ディレクトリも原本の配置を変えずにworkspace-hubから参照できる（SSOT維持）
- プロジェクト・研究・就活など複数ドメインの情報を横断的に活用できる

### 1.3 管理スコープ

以下のドメインを横断的に管理し、相互に参照・活用する:

- 大学研究
- 企業インターン
- 個人開発
- 就活（軸の整理、ポートフォリオ、強み作り）
- mind（思考・意思決定・バックログ）

### 1.4 接続先環境

- 自宅のLinuxサーバ
- 大学のスパコン

## 2. 機能要求

### FR-1: Git一括同期

- YAMLマニフェストで管理対象リポジトリを宣言的に定義できる
- 1コマンドで全リポジトリのclone/fetch/pullを実行できる
- 同期結果のサマリーを出力する（成功/失敗/変更有無）
- 新規リポジトリの追加はマニフェスト編集のみで完結する

### FR-2: リモートファイルシステム統合

- リモートPCのディレクトリをローカルマウントポイントに透過的にマウントできる
- マウント対象はマニフェストで宣言的に定義する
- マウント/アンマウントを1コマンドで実行できる
- マウント状態の確認ができる

### FR-3: リモート操作

2つのモードを提供する:

**コマンド実行モード:**
- `hub exec <host> <command>` のような形式でリモートにコマンドを投げられる コマンド名はあくまで例
- リモートの特定ディレクトリでのコマンド実行を指定できる（例: 訓練の実行、特定ワークスペースでのClaude起動）
- 実行対象ホストはマニフェストから解決する
- 標準出力/標準エラー出力をローカルに返す

**対話的SSH接続モード:**
- 登録済みホストにコマンド1つでSSH接続できる
- 親ディレクトリへの移動やより高度な操作など、自由な対話操作が可能

### FR-4: AIコンテキスト自動注入

- メタリポのCLAUDE.md（俯瞰用）と各プロジェクトのCLAUDE.md（作業用）の二層構成
- 同期実行時に各リポジトリ・マウントの状態サマリーを自動生成する
- mind/ディレクトリで人間の意図・判断・バックログをAIに渡せる

### FR-5: Agentルール一括配布

- AIエージェントの共通規約（CLAUDE.md）、Skill、MCP設定、権限設定をworkspace-hubで一元管理する
- 1コマンドで登録済み全ワークスペースにAgentルール群を一括配布・更新できる
- 従来の.my-bootの役割をworkspace-hubに統合する
- 各プロジェクトを直接開いて作業した場合でも、配布済みのルールが適用される

### FR-6: 統合ディレクトリツリー

- 画面上は1つのディレクトリツリーとして見える
- 実体はローカルのシンボリックリンク + リモートのSSHFSマウントで構成される
- ディレクトリ構成はマニフェストにより決定する

### FR-7: ローカルワークスペース統合

- ローカルの既存ディレクトリ（例: `書類/研究/`）を、ファイルを移動せずにworkspace-hubから参照できる
- 原本は元のパスに残り続ける（SSOTの維持）
- 特定のサブディレクトリを除外できる（例: ポスター資料は除外）
- Git管理していない大容量ファイルも含めて参照できる

## 3. 非機能要求

### NFR-1: 環境

- macOSではmacFUSE + sshfsのインストールが前提（Homebrew経由）

### NFR-2: セキュリティ

- SSH公開鍵認証を前提とする
- マニフェストにパスワード・秘密鍵等の機密情報を含めない
- マニフェスト自体はGit管理可能な形式とする

### NFR-3: パフォーマンス

- SSHFSはブラウズ・確認用途と位置づけ、大容量データの直接処理は行わない
- 学習・推論等の計算処理はリモート側で直接実行する方針

### NFR-4: 運用

- 設定変更はマニフェストファイルの編集のみで完結する
- 追加のサーバーソフトウェアのインストールを要求しない（SSH以外）
